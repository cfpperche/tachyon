## HIGH — awaiting-human can get stuck after a same-turn prompt enters `needs-input`

The delta removes the old clear-on-content path and now clears only inside `transition()` when the previous state is exactly `idle` and the next state is `working`:

- `src/attention/AttentionMonitor.ts:414-423` computes `isNewTurnEdge = snap.state === "idle" && state === "working"` and clears `awaitingHuman` only under that condition.
- `src/attention/AttentionMonitor.ts:321-339` preserves `awaitingHuman` while a recognized prompt/error pattern stabilizes and transitions the agent to `needs-input` or `throttled`.
- `test/unit/attention.test.ts:515-525` explicitly asserts that same-turn recognized prompt output does not clear the latch and leaves it set while the state becomes `needs-input`.

That protects the previous HIGH from same-turn output, but it leaves a realistic stuck-badge path:

1. Agent calls `request_human_attention`; `flagAwaitingHuman()` sets `awaitingHuman = true`.
2. The same agent turn renders a recognized prompt, such as `Continue? [y/n]`. The new test confirms this becomes `needs-input` while the latch remains true.
3. The human answers the prompt. Existing attention behavior transitions from `needs-input` back to `working` on the next content change; `test/unit/attention.test.ts:443-451` covers this `needs-input -> working` rescue shape for connection-drop recovery.
4. Because `transition()` only clears on `idle -> working`, the human-answer turn does not clear `awaitingHuman`. The badge remains even though the human responded and the agent is acting on that response.

This is a direct miss on the brief's "any path where the latch never clears (stuck badge)" adversarial check. It may eventually clear on a later, unrelated `idle -> working` transition, but it stays stale across the response turn that should clear it. The fix needs to treat the human-response working edge after the latch was set as the clear boundary even when the prior state is `needs-input`/`throttled`, while still excluding output from the same already-working turn.
