# t-0918a0

Root cause: Bridge timed the full HTTP lifetime for every MCP request and marked anything over the 10s slow metric threshold as `slow`. Workspace then converted every slow completion into a warning toast that only included the duration.

The dogfood `973895ms` toast is consistent with a legitimate long-lived Bridge MCP call, most likely `wait_for_agent`: the request intentionally blocks while waiting for another agent state change, so the Bridge request duration can be many minutes without indicating Bridge overhead or a stuck extension host.

Fix: request completion events now include best-effort tool and caller/claimed identity context. Workspace keeps the 10s slow metric, but only toasts extreme slow requests, suppresses known long-running tools, and rate-limits identical warning toasts.
