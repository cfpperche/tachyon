Modelo mental (não é 1 chip por status)

O runtime já tem 8 statuses finos (running · needs · throttled · idle · stopping · stop-failed · stopped · crashed). No sidebar denso, isso vira ruído. O filtro usa 3 buckets de intenção + All — o mesmo idioma dos dots, sem reinventar taxonomia.

Mapeamento

ChipIncluiPergunta que responde
Live running needs throttled idle stopping stop-failed Quem ainda tem sessão / processo?
Needs you needs throttled stop-failed + awaitingHuman / attention Onde preciso intervir agora?
Stopped stopped crashed Quem está morto / resumable / limpar?
Na sua frota do print: Live = 4 (claude idle, codex working, codex-regression stop-failed, grok idle) · Needs you = 1 (codex-regression) · Stopped = 4 (budget, soul, claudex, hermes). Um clique em Stopped esconde o ruído dos vivos e deixa o cemetery legível.

Regras de UX (v1)

  • Single-select — um chip ativo; clicar de novo no ativo volta para All (toggle).
  • Contagem no chip — sempre do total da frota, não do subconjunto filtrado (âncora estável).
  • Chip zero — desabilitado visualmente (opacity), sem esconder o slot (layout estável).
  • Não reagrupa — a lista continua flat + hierarchy parent/child; só esconde rows. Spec 242 se mantém (status não reordena).
  • Hierarquia — se um filho match e o pai não, o pai aparece como âncora dimmed (v1.1); v1 simplesmente mostra o filho solo.
  • Persistência — opcional em globalState por seção (como sort), default All. Não multi-root diferente.
  • Pins já filtram por tag — mesmo padrão mental: filter local da seção, não global da busca Ctrl+K.
