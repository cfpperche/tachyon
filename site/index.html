Agent Pipelines

Orchestrate your agents into a one-shot chain

Stop hand-sequencing a multi-step task through the Bridge. Compose the agents you've already configured into a pipeline — a declarative chain that runs plan → implement → review end-to-end, with a shared git worktree flowing down the steps and a human gate wherever you want one. It's the difference between babysitting each call and approving the result.

  • A reusable workflow, run per issue — declare input: required and the same pipeline becomes your team's process: ▶ Run opens an input file, you paste the issue, and each node is a persona whose work is that input plus the upstream context (no hard-coded task)
  • The worktree IS the state — the run owns one git worktree that flows down the chain, so a downstream node sees exactly what the previous one wrote; an optional summary on completion hands the next node the narrative ("plan in docs/plan.md; chose CSS vars")
  • A real done-signal, never "idle" — a node finishes on a process exit, a verify gate, or an explicit signal; a no-op that changed nothing fails as stale; every node has a timeout and fails closed
  • Human approval gates — gate: approve pauses the run for your Approve/Reject; a failed node holds its downstream visibly blocked — no silent wedge, no auto-retry
  • Any runtime as a node — a persistent specialist (agent:), a non-interactive one-shot (npm test), or an ephemeral LLM (codex/claude); claude and codex both reach the completion signal — Tachyon wires the Bridge into both automatically
  • From the sidebar — ▶ Run, watch each node's live status, View Changes (the run-worktree diff), and ↻ Re-run from any step (reusing the upstream work)
Observability

Know which agent needs you

With several agents running, the expensive part is noticing which one stopped. Tachyon watches every pane and tells you — and your other agents — exactly who is running, who is idle, who crashed, and who is waiting for your answer.

  • needs you — high-precision prompt detection ([y/n], confirmations, selectors): yellow bell, a badge on the ⚡ icon, one toast with an Open button
  • idle — CPU-aware silence: a thinking agent is never flagged as stuck
  • crashed — exit N — the dead pane is kept frozen for postmortem; opt-in auto-restart with backoff and a crash-loop guard
  • Every state is exposed to orchestrating agents via list_agents — a parent can spot a stuck sibling and answer it
Session resume

Survive a reboot, not just a restart

A VS Code restart leaves the tmux sessions alive. A machine reboot, wsl --shutdown, or an OOM kill takes the whole server down — and every agent with it. Reopen the folder and Tachyon brings them back with their conversation, not zeroed.

  • Records each agent's session at spawn — claude runs a named session (-n) and Tachyon captures its real id from the transcript (exact even with many claude agents in one folder); gemini mints --session-id; codex/opencode resolve by working directory
  • On reopen, dead agents respawn with their resume command — claude --resume, codex resume, qwen --continue — and pick up where they left off
  • Declared autostart agents resume automatically; ad-hoc ones are offered with one-click Resume all
  • Honest badge — a stopped agent shows · resumable only when its transcript is really on disk, or · fresh start when it's gone, so ↻ never surprises you with a blank slate
  • In-process and per-workspace — no global tmux config, no daemon, no boot hook

Config as code

Your whole fleet in one tachyon.yml

Define every agent and process once. Commit it to the repo. Your teammate clones, opens the project, and gets the exact same workspace — same agents, same instructions, same commands.

  • Per-agent env, working dir, auto-start and watch-restart
  • Role instructions injected as the agent's startup prompt
  • Curated commands & gated runbooks agents can run safely
  • Sensible tmux defaults (mouse, scrollback, focus tracking) — override or extend any in settings.tmux; your ~/.tmux.conf is never touched
  • Your comments survive every UI edit — the file stays the source of truth
 tachyon.yml
# Your whole fleet, versioned in git
agents:           # AI CLIs
  claude:
    cmd: claude
    autostart: true
    instructions: "Senior engineer. Ship clean PRs."

terminals:        # servers, shells, builds
  dev:
    cmd: npm run dev
    watch: "src/**"

commands:
  test: {cmd: npm test}
  lint: {cmd: npm run lint}

runbooks:
  ship:
    steps: [lint, test, ./deploy.sh]

settings:
  tmux:            # defaults on: mouse, focus-events, history-limit
    history-limit: 50000
The Bridge — built-in MCP server

One agent becomes a fleet

Tachyon runs a local MCP server per workspace. Your agents use it to spawn sub-agents, read each other's output, type into each other's terminals, and ping you when they're done — and the whole tree is right there in your sidebar.

  • ⚡

    Spawn on demand

    An agent calls spawn_agent with a role prompt to delegate to a fresh sub-agent — children are full agents and can spawn their own.

  • ⛶

    Workspace-isolated

    Each folder gets its own Bridge, port and token. Sub-agents only see siblings in their own workspace — no cross-talk.

  • 👁

    You stay in the loop

    Every sub-agent appears in the tree with live status; orphans are promoted, never cascade-killed, and any agent can toast you with notify.

Worktree isolation

Parallel agents that never clobber each other

Set worktree: true and an agent runs in its own git worktree on its own branch — its edits never touch your main tree, and its work becomes one clean, reviewable, mergeable branch. It's pure git, so it works for any runtime and any kind.

  • Branch resolves per-agent › global template › tachyon/<agent>; central, out-of-tree checkouts keyed by workspace
  • Sub-agents share the parent's worktree — one unit of work, one branch, one PR
  • worktreeSetup seeds the fresh checkout (install deps, copy .env) once on create
  • Verify gate — declare verify: and a ✓/✗/⊘ badge proves the branch is shippable; verify_agent lets a parent gate a merge on "done and green"
  • Create PR — one click pushes the branch and opens a GitHub PR via gh, the ✓/✗/⊘ verify verdict carried into the body; human-triggered (review the title + body first), never automatic — isolate → review → verify → ship
  • Cleanup is human-decided on dismiss — shows uncommitted + commits-ahead/unpushed, and never force-deletes unmerged work in one click

Review the agent's branch in the native diff editor, then merge with plain git.

Isolated harness · new in 0.23

Give one agent its own MCP, skills, rules & hooks

By default every agent shares the same config (your project .mcp.json + your global setup). Add a per-agent harness: block — or toggle Isolated harness in Agent Studio — and one agent gets its own MCP servers, skills, rules, and hooks that never leak to the rest of the fleet. Tachyon gives it a private config home and runs it with --strict-mcp-config.

  • No leak — the agent sees only what you declared (plus the Tachyon Bridge, always injected so it can still coordinate); no sibling agent sees it, and it doesn't pick up the project/global servers
  • MCP · skills · rules · hooks — declare any combination; skills resolve via /<name>, rules become the agent's own CLAUDE.md, hooks fire only for it
  • inherit: workspace folds in your project .mcp.json + the agent's extras; none is a clean slate — but the Bridge is injected either way
  • Secrets stay off disk — values are ${VAR} references; Tachyon resolves them from a project .env (or your shell) and injects them at spawn, failing fast if one is missing
  • Auth just works — the private home is symlinked to your real Claude login (no copying keys around)
  • Survives restart & resume; a ⚙ badge marks it in the sidebar. claude-only today — codex is next.
 tachyon.yml
agents:
  researcher:          # its own MCP, scoped to itself
    cmd: claude
    harness:
      inherit: workspace   # none | workspace
      mcp:
        tavily:
          command: npx
          args: ["-y", "tavily-mcp"]
          env:
            TAVILY_API_KEY: ${TAVILY_API_KEY}

Commands & Runbooks

Exit code is the result

Agents run forever; commands run once — exit 0 is a green ✓, non-zero is a red ✗ with the dead pane kept for postmortem. Runbooks chain them with an exit-code gate: the first failure stops the procedure and keeps the evidence.

  • One click for you (▶ in the sidebar), one blocking call for agents (run_command)
  • A vetted alternative to agents typing arbitrary shell
  • Failed step reopens its frozen output — inspect exactly what happened
Schedules

Runtime-neutral cron, human-gated

Claude has /schedule; Codex, Gemini and OpenCode have nothing. A schedules: map gives any runtime cron-like timers over the executors you already have. They fire only while the workspace is open — no daemon, no unsupervised agents waking at 3am.

  • every: 1h or at: "09:00" → run a command/runbook or spawn an agent
  • Agents can propose_schedule — but the proposal is inert until you approve it (approval writes it into tachyon.yml)
  • No agent schedules itself into action without your sign-off
Pins

Pin it now, deal with it later

Findings shouldn't die in scrollback. Every workspace gets a shared checklist — yours in the sidebar, your agents' over MCP, and your team's as a plain file (.tachyon/pins.json) you can commit.

  • Agents create and check off pins over MCP — they track their own plan as they work
  • A plain file: readable by anything, committable if the team wants shared findings

Multi-root

Workspace isolation, for real

Two folders in one VSCode window — an API and its worker. Each gets its own Bridge (note the two ports), its own agents, commands and pins. The status bar says ⚡ Tachyon ×2.

  • Own tmux namespace, Bridge port and token per folder — sub-agents can't cross-talk
  • Palette commands ask which folder; tree items act on their own folder
  • Folders added or removed live are picked up without a reload
Server Inspector

See the whole tmux server

The sidebar shows what this folder owns. The inspector opens an editor view over the entire dedicated tmux -L tachyon socket — every session, across every open folder and the orphans a closed window left behind — grouped by workspace then kind, each with its live / exit-code badge, pid and command.

  • Cross-workspace — agents, commands, runbook steps and orphaned sessions, with busy/idle and uptime
  • Per session: Open (attach in a terminal), Capture, Kill — plus one-click Kill-all-dead and Reap-orphans
  • Only Tachyon's dedicated socket, never your own tmux — Kill stays safe by design
Agent Studio

Manage everything from the UI

One form, five tabs — Agent, Terminal, Command, Runbook, Schedule. Quick-add chips for the AI CLIs detected on your machine, per-runtime flag chips, role instructions. Every edit goes through the same comment-preserving pipeline as hand-editing.

Security

Local by design

  • Loopback only — the Bridge binds to 127.0.0.1, never the network. No cloud, no telemetry, no account.
  • Bearer auth by default — per-workspace token in the extension's private storage, referenced via env var, never written to a committable file; injected automatically into every spawned session.
  • Workspace isolation — sessions, port, token and pins are namespaced per folder; Tachyon runs its own tmux server, your ~/.tmux.conf is never touched.
  • Guardrails — maxAgents caps concurrent sessions (no fork-bombs); destructive UI actions confirm or refuse while running.
