What it is

Tachyon turns VSCode into a cockpit for running several AI coding agents at once. Each agent is a tmux session (the process source of truth — it survives editor restarts) shown as a native editor-area terminal. An embedded MCP Bridge lets agents spawn, watch, and coordinate each other.

Highlights

tmux-backed

Sessions outlive the window; crashes leave a postmortem pane with the exit code.

The Bridge (MCP)

16 tools — spawn/kill/restart, read/write, wait, pins & notes, run commands & runbooks.

Attention detection

Knows when an agent is waiting for you — sidebar badge + toast, event-driven via tmux control mode.

Agent Studio

Create/edit agents, terminals, commands & runbooks — theme-aware, en/pt-BR.

Lineage & delegation

Agents spawn sub-agents; the sidebar nests them; wait_for_agent closes the loop.

Multi-root

One isolated Workspace per folder — own namespace, Bridge, and token.

Agents that spawn agents

Any connected agent can spawn sub-agents — with their own role prompt and declared lineage (the sidebar nests children under who spawned them; orphans are promoted, never cascade-killed). They talk through three concrete channels, all mediated by the Bridge: the terminals themselves (read_output / write_input — read a sibling's pane, type into it), synchronization (wait_for_agent, event-driven — no polling), and shared memory (notes & pins as durable handoff, plus notify to toast the human).

spawn_agent  name=worker cmd=claude parent=claude
             instructions="research X; save findings with set_notes; then notify"
wait_for_agent  name=worker until=idle      # blocks, event-driven
get_notes                                   # collect the result
kill_agent   name=worker                    # tidy up

Quick start

# a tachyon.yml in your project root:
agents:
  claude:
    cmd: claude
    autostart: true
  shell:
    cmd: bash

# then: install the extension, open the folder — agents boot into editor terminals.

Requires tmux (WSL / Linux / macOS).
